Calculating schedules in LeanCPM is slightly different than in legacy CPM.

## Main Differences from legacy CPM

1. There is no concept of constraints (As soon as possible, Start no earlier than, etc.)
2. There is no data date, only Today
3. [Nominal](terms/nominal_dates) Start & Finish dates are independent of schedule calculations
4. There are only two types of dependencies (relationships)
	- **Series**: A blocker must finish before the blocked task can start; lag is not allowed
	- **Parallel**: A start-start and finish-finish relationship with an optional lag
5. Milestones can only be in series with their dependents and dependencies
6. Schedules are calculated in days, not minutes or seconds.

## What is ignored

Anything that has a “canceled” [status](status) is not considered in the calculation.

In LeanCPM, any task, regardless of status, whose nominal Start or Finish is before Today isn’t used for the calculation; however, any residual calculated [fields](#what-exactly-is-calculated) from previous calculations will remain and be used for current calculations.

For example, if Task A was set to start next week with an early start of today and the schedule were calculated today, all of the relevant fields from above would be calculated. Fast-forward two weeks, and the schedule hasn’t been calculated since, but is now triggered. Task 2 will still show an early start of one week ago.

## What is required

To figure out the soonest a task can start (early start), we must look at its blockers. The soonest a task can start is right after the soonest its blocker can finish (or start if it's in parallel).

If an un-started task has no blockers, we shouldn’t assume it can start now. However, if it has blockers that are cleared, we should assume it is ready and can start as early as today.

<Callout title="Cleared blockers" type="info">
A cleared blocker is a task or issue that *was* blocking another task or issue but is no longer because it or the task it’s blocking has already started or finished, depending on its dependency type.
</Callout>


If you look at a given task’s blocker, then its blocker, and so on, you eventually get to a task without a blocker. Since tasks in LeanCPM don’t have constraints, it’s impossible to find the earliest a task can occur without either a cleared blocker, a [milestone](terms/milestone), or an [issue](terms/issue) that kicks off the dependency path.

The same is true when calculating late dates. 

Therefore, in a given [dependency path](terms/dependencies#dependency-path), it'll be impossible to calculate the total float, drag, and priority of the tasks that are not between a cleared blocker, milestone, or issue.

#### B. For each in parallel

1. Set task’s `early_start` to blocker’s `early_start` + `lag` 
2. Set task’s `early_finish` to the *later* of:
	-  Blocker’s `early_finish` (do not add the lag) OR 
	-  Task's `early_start + duration`
3. Milestones cannot be in parallel with other Tasks or Milestones
